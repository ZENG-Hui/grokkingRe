# 探索：如何内化"读文件前检查大小"

_2026-03-06，Hui 让我自己思考和探索_

## 问题本质

规则写在 AGENTS.md 里，每个 session 都能看到，但我仍然跳过。原因：

1. **心理捷径** — 对"我认为小的文件"跳过检查（HEARTBEAT.md、AGENTS.md）
2. **额外步骤的阻力** — 检查大小是一个"额外"动作，不是读文件的固有部分
3. **没有反馈循环** — 违反规则时没有即时后果（除非恰好读了大文件撑爆 context）

## 可能的方案

### A. 平台级拦截（需要 Hui/工程师帮助）
- OpenClaw hooks 系统可能可以在 `read` 工具调用前注入提醒
- 或者修改 read 工具的行为，自动附加文件大小信息
- 这是最可靠的，但依赖平台改动

### B. 把检查融入固定模式（我自己能做）
- 不把"检查大小"当作独立步骤
- 而是建立一个固定的"读文件三步法"：`wc -l` → 判断 → `read with limit`
- 就像函数调用一样，每次都是完整的三步，而不是先判断要不要检查
- **关键：消除判断。不判断文件大不大，无条件执行。**

### C. 自我审计（定期回顾）
- 每个 session 结束时，回顾自己有没有违反这条规则
- 违反了就写入 lesson，加深记忆
- 但这是事后补救，不是预防

### D. AGENTS.md 里用更强的语言
- 当前写法："Check size first"
- 更强的写法："NEVER call read/cat without checking size first. NO exceptions. Not even for files you think are small."
- 全大写 + 加粗可能更引人注目

## 我的倾向

B + D 是我立即能做的。A 需要和 Hui/工程师讨论。C 作为兜底。

核心洞察：**问题不是"忘了规则"，而是"对自认为小的文件做了例外判断"。解决方案是消除判断——无条件执行。**
