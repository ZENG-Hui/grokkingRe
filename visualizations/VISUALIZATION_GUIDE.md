## 1. Weight Sparsity Heatmaps
**File**: `weight_sparsity_heatmaps.png`

### What it shows
Visual representation of the sparse connectivity pattern in each weight matrix of the model.

### Axes
- **X-axis (Horizontal)**: Input dimension
- **Y-axis (Vertical)**: Output dimension
- Each subplot represents one weight matrix from the model

### Color Encoding
- **Green/Yellow**: Non-zero weights (active connections)
- **Red/Dark**: Zero weights (pruned connections)
- **Color scale**: 0 (no connection) → 1 (active connection)

### How to Interpret

#### ✅ Good Sparse Pattern
```
Structured Sparsity:
████░░░░░░░░  → Some neurons fully connected
░░░░████░░░░  → Others sparse
░░░░░░░░████  → Clear block patterns
```
- Clear structure or patterns
- Some fully connected blocks
- Reasonable distribution

#### ⚠️ Problematic Pattern
```
Extreme Random Noise:
█░█░░█░░█░░█  → Too scattered
░█░░█░█░░░█░  → No clear pattern
█░░█░░█░░█░░  → Hard to interpret
```
- Completely random scatter
- No recognizable structure

#### 📊 What to Look For
1. **Block structures**: Indicate learned features
2. **Diagonal patterns**: Common in residual connections
3. **Empty rows/columns**: Dead neurons (should be minimal with min_connections constraint)
4. **Density variation**: Different layers have different sparsity needs

### Title Information
Each subplot shows:
- **Layer name** (e.g., `blocks.0.self_attn_norm.weight`)
- **Matrix shape** (e.g., `[64, 64]`)
- **Sparsity ratio** (e.g., `10.23%` means 10.23% of weights are non-zero)

## 2. Layer Sparsity Statistics
**File**: `layer_sparsity_stats.png`

### What it shows
Two horizontal bar charts comparing sparsity and parameter counts across all layers.

### Top Chart: Sparsity per Layer

#### Axes
- **X-axis**: Sparsity ratio (0.0 to 1.0)
  - 0.0 = completely sparse (0% non-zero)
  - 1.0 = fully dense (100% non-zero)
- **Y-axis**: Layer names (from top to bottom)

#### Color Encoding
- **Color gradient**: Viridis colormap (purple → yellow)
- Different colors help distinguish layers
- No specific meaning to color itself

#### How to Interpret
- **Longer bars** (closer to 1.0): More dense, more non-zero weights
- **Shorter bars** (closer to 0.0): More sparse, fewer non-zero weights
- **Uniform lengths**: Consistent sparsity across layers (expected with our Top-K method)
- **Varying lengths**: Some layers preserve more connections than others

### Bottom Chart: Parameters per Layer

#### Axes
- **X-axis**: Total number of parameters
- **Y-axis**: Layer names (same order as top chart)

#### How to Interpret
- **Longer bars**: Layers with more parameters
- **Shorter bars**: Layers with fewer parameters
- Compare with top chart to see: **large layers that are sparse** = **biggest compression gains**

### What to Look For
1. **Embedding layers**: Often have different sparsity than transformer blocks
2. **Attention vs FFN**: FFN layers typically have 4x more parameters
3. **Consistency**: Our Top-K method should create similar sparsity ratios across layers

## 3. Weight Distribution
**File**: `weight_distribution.png`

### What it shows
Four subplots analyzing the distribution of non-zero weight values.

### Subplot Layout
```
┌─────────────────┬─────────────────┐
│ Linear Scale    │ Log Scale       │
│ Histogram       │ Histogram       │
├─────────────────┼─────────────────┤
│ Absolute Value  │ Statistics      │
│ Distribution    │ Text Summary    │
└─────────────────┴─────────────────┘
```

### Top-Left: Linear Scale Histogram

#### Axes
- **X-axis**: Weight values (can be negative or positive)
- **Y-axis**: Frequency (number of weights)

#### How to Interpret
- **Bell curve**: Normal distribution (common)
- **Peak at zero**: Would indicate dead weights (shouldn't happen - we only plot non-zero!)
- **Symmetric**: Weights balanced around zero
- **Heavy tails**: Some very large magnitude weights

### Top-Right: Log Scale Histogram

#### Axes
- **X-axis**: Weight values
- **Y-axis**: Frequency (logarithmic scale)

#### Purpose
- Better visualization when some bins have very few samples
- Reveals long-tail distributions

### Bottom-Left: Absolute Value Distribution

#### Axes
- **X-axis**: |Weight value| (always positive)
- **Y-axis**: Frequency

#### Color
- **Orange**: Distinguishes from the blue histograms above

#### How to Interpret
- Shows magnitude distribution regardless of sign
- **Peak near zero**: Many small-magnitude weights kept (might indicate aggressive sparsity)
- **Peak away from zero**: Top-K selected larger weights (expected!)
- **Uniform**: Wide range of weight magnitudes

### Bottom-Right: Statistics Panel

#### What it shows
Key statistical measures (text format):
- **Total Weights**: Number of non-zero weights analyzed
- **Mean**: Average weight value (should be close to 0 if balanced)
- **Median**: Middle value (less sensitive to outliers)
- **Std Dev**: Standard deviation (spread of distribution)
- **Min/Max**: Range of values
- **Abs Mean**: Average magnitude (always positive)

#### What to Look For
1. **Mean ≈ 0**: Weights are balanced (good)
2. **Abs Mean > 0**: How "strong" the average weight is
3. **Std Dev**: How varied the weights are
4. **Min/Max range**: Check for outliers or numerical issues

### What it shows
Detailed view of attention layer weight matrices (Q, K, V projections).

### Axes
- **X-axis**: Input dimension

- **Blue gradient** (light → dark)

### Title Box (Top-left of each subplot)

### How to Interpret

#### Self-Attention Patterns
Attention layers are critical for the model's ability to process sequences. Look for:

1. **Full rows**: A query attends to many keys
2. **Full columns**: A value is used by many outputs
3. **Block diagonal**: Local attention patterns
4. **Scattered**: Selective long-range attention

#### What Different Patterns Mean

**Dense blocks**:
```

```

## 🎯 Overall Interpretation Guidelines

### Signs of Successful Sparse Training

1. **Sparsity Ratio Close to Target**
   - If target L0 = 0.1, expect ~10% non-zero weights across layers

2. **Structured Patterns**
   - Not completely random
   - Some recognizable structures in heatmaps

3. **Reasonable Weight Magnitudes**
   - No extreme outliers
   - Distribution makes sense (centered around zero)

4. **Layer-wise Consistency**
   - Similar sparsity ratios if using uniform Top-K
   - Explainable variations if different

### Red Flags to Watch For

1. **Empty Layers**
   - Entire rows/columns of zeros
   - Indicates dead neurons (though our min_connections constraint should prevent this)

2. **Extreme Imbalance**
   - One layer 90% sparse, another 1% sparse (without good reason)

3. **Numerical Issues**
   - Weights all exactly the same value
   - NaN or Inf values

4. **No Clear Patterns**
   - If all heatmaps look like random noise, training might not have converged well

## 💡 Practical Tips

### Comparing Different Runs

To compare sparse models trained with different hyperparameters:

1. **Generate visualizations for each**:
   ```bash
   python visualize_sparsity.py --model run1/final_model.pt --output vis_run1
   python visualize_sparsity.py --model run2/final_model.pt --output vis_run2
   ```

2. **Compare side-by-side**:
   - Sparsity ratios (are they achieving target L0?)
   - Pattern structures (which looks more organized?)
   - Weight distributions (similar shapes?)

### Quick Diagnosis Checklist

- [ ] Sparsity ratio matches target L0? (check layer stats)
- [ ] Weights centered around zero? (check distribution mean)
- [ ] No dead neurons? (check heatmaps for empty rows/cols)
- [ ] Reasonable compression ratio? (check README.md summary)
- [ ] Patterns make sense? (block structures, not pure noise)

## 📚 Related Concepts

### Top-K Sparsification
Our training uses **Top-K** weight selection, which:
- Keeps only the K largest (by absolute value) weights per layer
- Zeros out all others
- Results in uniform sparsity ratios across matrices

This is why you should see **similar sparsity percentages** across different layers.

### L0 Annealing
During training, the target sparsity (L0) gradually decreases:
```
Step 0:     L0 = 1.0  (100% dense)
Step 2500:  L0 = 0.5  (50% dense)
Step 5000:  L0 = 0.1  (10% dense, 90% sparse) ← final target
```

The visualizations show the **final state** after annealing completes.

### Activation Sparsity vs Weight Sparsity
- **Weight sparsity** (what we visualize): Connections in the network
- **Activation sparsity** (AbsTopK): Values during forward pass
- Both work together to create interpretable circuits
